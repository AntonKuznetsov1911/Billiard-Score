# Android 1.1.0 — подготовка выпуска

Пакет: io.github.antonkuznetsov1911.billiard. versionCode 2, versionName 1.1.0.
Минимальная версия: Android 7.0 (API 24). Целевая/компиляция: API 36.

## Изменения

- Системная отправка CSV/JSON через Android и текстов результатов/приглашений.
- Печать через системный диалог Android, включая «Сохранить как PDF».
- Кнопка «Назад» закрывает открытый экран/диалог, затем сворачивает приложение; игра не отменяется.
- Сохранение ожидающих изменений при сворачивании.
- Принятые от клуба данные сразу сохраняются локально.
- Результат одной игры имеет одинаковый ID на всех устройствах.
- restoreAt отделяет восстановленный набор данных от прежнего.
- Журнал не обрезается после 3000 действий. При 20000 локальные добавления останавливаются с сообщением, сохраненный счет не теряется; пришедшие события сохраняются.
- В истории можно исправлять отдельные круги колхоза с согласованным пересчетом.
- Страница удаления аккаунта public/delete-account.html.

## Сборка

npm ci
npm test
npm run android:sync

Далее в папке android: gradlew assembleDebug lintDebug.
Для подписанных assembleRelease bundleRelease задайте переменные среды:
BILLIARD_KEYSTORE_PATH, BILLIARD_KEYSTORE_PASSWORD, BILLIARD_KEY_ALIAS, BILLIARD_KEY_PASSWORD.
Пароли и закрытый ключ не записывайте в репозиторий.

GitHub Actions «Android build» строит APK; при наличии секретов подписи — также APK/AAB выпуска. Конфигурация VITE_SUPABASE_URL/VITE_SUPABASE_ANON_KEY должна соответствовать рабочему серверу. В клиентской сборке допустим только публичный ключ; service_role запрещен.

## Совместимость клуба

Для серверного восстановления выполните обновленный supabase/history.sql после резервной копии базы. Выпуск Android и web следует согласовать: старые клиенты не понимают restoreAt. Восстановление общего состояния нельзя считать надежным при одновременной работе старых и новых клиентов. Обновление БД и web в рамках локальной подготовки не выполнялось.

## Проверка на телефоне перед магазином

1. Установить APK. Если уже есть версия с другой подписью — сначала экспортировать данные из нее; не удалять приложение с данными без копии.
2. Новая партия, счёт, отмена, завершение, повторная партия, история и статистика.
3. Кнопка Android «Назад» в игре, истории и диалогах; игра не должна исчезать.
4. Свернуть/закрыть приложение, открыть без интернета и проверить счет.
5. Отправить JSON-копию в Files/Диск/мессенджер, затем восстановить через системный выбор файла. Аналогично CSV; проверить русский текст.
6. Печать → Сохранить как PDF.
7. Вход в клуб по коду из письма, синхронизация двух телефонов, отсутствие сети и восстановление соединения.
8. Размер шрифтов Android, экран с вырезом, жестовая навигация, клавиатура.
9. Удаление аккаунта отдельного тестового пользователя (без удаления настоящих данных).

## Обновление 1.1.1 — Google-вход

Кнопка Google снова доступна в Android. Вход открывается через Capacitor Browser, Supabase использует PKCE; код обменивается на сессию внутри приложения. Провайдер Google уже был включен. Site URL и веб-redirect сохранены. Клиентские секреты Google не менялись.

После установки обновления: «Ещё» → «Войти через Google», выбрать аккаунт в браузере, подтвердить возврат в приложение, проверить появление своего email/клуба. Реальный вход пользователя на телефоне после обновления пока не подтвержден.
