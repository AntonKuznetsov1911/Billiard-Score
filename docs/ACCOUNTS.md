# Аккаунты и места хранения — 1.3.0-preview

## Как пользоваться

Без входа игроки и партии сохраняются на этом устройстве. В «Ещё → Аккаунт» можно войти через Google, код из письма или пароль существующего аккаунта. После входа открываются отдельные личные данные. Они автоматически синхронизируются с Supabase и доступны после входа в тот же аккаунт на другом устройстве. Клуб для личного облака не нужен.

Гостевые данные не присваиваются аккаунту автоматически. Кнопка «Добавить данные без аккаунта» добавляет их в личный профиль после подтверждения, сохраняя исходник гостя. Аккаунты A/B имеют отдельные личные данные, локальные копии, текущую партию и резервные снимки.

В существующий клуб можно перейти кнопкой «Открыть клуб…»; создание и вход по коду доступны в разделе клуба. «Мои личные данные» переключает место хранения, не выводя пользователя из клуба. Личное и клубное хранилища не смешиваются. Есть явные подтверждаемые копии в обе стороны; дальнейшие изменения копий независимы. Выбранный клуб запоминается для аккаунта. Общая настройка вибрации остаётся настройкой устройства.

Выход на этом устройстве не завершает сессии на остальных устройствах. Открывается прежний гостевой режим; локальные данные аккаунта сохраняются отдельно до следующего входа. Если срок сессии истёк без интернета, открывается локальная офлайн-копия последнего аккаунта. Она не выдаёт серверных прав: для синхронизации после подключения нужен действительный вход.

## Миграция прежних данных

Настоящие гостевые данные остаются гостевыми. Если прежняя общая запись содержит маркер синхронизированного клуба, она сначала архивируется отдельно. Только после проверки членства в том же клубе её данные восстанавливаются в соответствующее клубное хранилище. Затем серверная и офлайн-копии объединяются существующим механизмом mergeData. При первом переходе после обновления может понадобиться интернет, чтобы подтвердить членство. Неподтверждённая копия не удаляется и не присваивается случайному аккаунту.

## Синхронизация и защита

`personal_state` содержит одну запись на auth.users.id, каскадно удаляемую вместе с пользователем. RLS разрешает чтение только владельцу. Прямые insert/update/delete для клиентов запрещены. Запись через `save_personal_state` проверяет auth.uid(), ожидаемую серверную revision, форму JSON, размер до 2 МБ и лимит 120 записей/мин на владельца. При конфликте клиент заново читает и объединяет данные. В фоне изменения другого устройства подхватываются примерно каждые 30 секунд и при возвращении фокуса/сети. Свои изменения отправляются после короткой задержки. Подтверждение «сохранено в облаке» появляется после успешного обращения, ошибка оставляет локальную копию.

Состояние React перемонтируется при смене владельца/места хранения. Путь локального хранилища фиксирован для экземпляра; поздний ответ не применяется в другой профиль. Новая серверная запись никогда не использует владельца, переданного только клиентом, без проверки текущего auth.uid(). Резервные копии и текущая игра тоже разделены по местам хранения.

Для новой базы выполнить `supabase/personal-state.sql` после `security-2026-11-06.sql`: используется общий триггер валидации. На действующем проекте миграция уже применена. Анонимное чтение таблицы/вызов записи проверены через настоящий REST: 401 / 42501. Проверки owner/RLS/CAS/удаления выполнены в SQL Editor на временных записях с ROLLBACK; 15 дополнительных SQL-проверок — в изолированном PGlite.

## Удаление

Удаление аккаунта убирает его личную облачную запись, членства и соответствующие локальные профили на текущем устройстве. Гость и другие аккаунты остаются. Клубы последнего участника удаляются прежней серверной функцией, общая история остальных участников сохраняется по действующим правилам. Копии на других устройствах и ручные экспорты удаляются отдельно.

«Удалить мои данные с устройства» очищает все локальные профили и гостя, но не серверные данные. При ошибке выхода очистка не выполняется молча. «Очистить все данные» внутри рабочего режима действует на текущие игровые данные, а не на все аккаунты.

## Границы проверки

Фото профиля игрока загружается через «Фото / иконка», автоматически уменьшается до компактного JPEG и сохраняется вместе с данными выбранного рабочего пространства. Оно включается в резервные копии и синхронизируется так же, как остальные данные игрока; участники выбранного клуба могут его видеть. Фото можно заменить или удалить, выбрав вместо него готовую иконку.

Локальное разделение — разделение внутри приложения, а не шифрование против владельца/администратора устройства. Изоляция серверных данных обеспечивается RLS/RPC. Обычные ограничения localStorage и облачного JSON сохраняются; крупный импорт может остаться только локально с сообщением об ошибке облака. Google-вход на телефоне и реальные две физические установки новой версии ещё требуют пользовательской проверки. Браузерные сценарии используют подменённый backend; серверные права отдельно проверены на настоящем Supabase.
