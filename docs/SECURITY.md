# Безопасность приложения

## Доступ к данным

Клиент содержит только публичный Supabase publishable/anon ключ. Привилегированные ключи, пароли, закрытые ключи выпуска и Telegram-токен хранятся вне репозитория.
Сборка проверяет HTTPS URL, полноту публичной конфигурации и тип ключа. Чувствительные VITE-переменные запрещены.
JWT пользователя передаётся в Authorization. Запросы клиента используют credentials omit. OAuth использует PKCE. Для native callback допускается один точный адрес.
Данные авторизации хранятся SDK в локальном хранилище. Любой исполняющийся в контексте приложения вредоносный JavaScript может получить эту сессию. CSP и вывод React защищают от проверенных сценариев XSS. HttpOnly недоступен для такой клиентской модели авторизации.

## Серверная установка

Для новой базы выполнить schema.sql, feedback.sql, security.sql, account.sql, затем security-2026-11-06.sql. Для существующей базы перед изменением сверить объекты и политики. Миграция security-2026-11-06.sql поддерживает наличие или отсутствие таблицы истории.
Не запускать после неё старый hardening.sql или security.sql без повторного применения новой миграции, они заменяют функцию вступления старой реализацией.

Проверять RLS на всех доступных через API таблицах и права выполнения security definer функций.
Допускать анонимно только вставку проверенного отзыва и ограниченную RPC телеметрии.
Создание клуба ограничено 20 в день на аккаунт. Вступление ограничено 10 запросами за 15 минут на аккаунт. Отзывы ограничены 5 за 10 минут на вошедший аккаунт и 60 за 10 минут на проект. Телеметрия ограничена 60 новыми записями в минуту на проект. Общие бюджеты не заменяют защиту на уровне IP и CAPTCHA.
Валидатор клуба проверяет код/имя, размер состояния меньше 2 000 000 байт, основные массивы, имена/идентификаторы игроков, структуру участников и числовой счёт. Клубные данные пишутся участниками клуба, участники доверяют друг другу ведение счёта.

Удаление аккаунта удаляет членство, клуб последнего участника, связанные с user_id отзывы и аккаунт. Общая история других участников остаётся общей. Копии отзывов, пересланные в Telegram, требуют отдельного процесса удаления по запросу.

## Файлы и Android

Импорт принимает JSON-файлы до 20 МиБ и проверяет структуру до замены данных. Значения дополнительно нормализуются. Файл открывается локально и не загружается в Supabase Storage.
Android запрещает незашифрованный сетевой трафик. Системное резервирование и перенос данных приложения отключены, чтобы не переносить сессии. Пользовательские JSON-копии доступны в приложении и не включают токены.

## HTTP и хостинг

HTTPS и HSTS должны действовать на публичном сайте и API. Сборка добавляет CSP и Referrer Policy в HTML.
Vite dev/preview устанавливают X-Frame-Options, nosniff, Referrer-Policy, Permissions-Policy и frame-ancestors.
На GitHub Pages конфигурация Vite HTTP-заголовков не применяется. Для полного набора HTTP-заголовков требуется настроить хостинг или пограничный прокси. Не считать meta CSP заменой frame-ancestors.
proxy/nginx.conf содержит шаблон ограничения Origin, частоты запросов, размера тела, HTTPS и проверки сертификата upstream. Это шаблон для собственного сервера. Его нужно проверить nginx -t на целевом хосте и адаптировать домены.
Supabase Data API допускает кросс-доменные клиенты. Ограничение CORS собственного прокси не запрещает прямые обращения к управляемому API. Авторизация и RLS обязательны в обоих случаях.
